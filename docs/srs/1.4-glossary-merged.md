## 1.4 Definitions & Acronyms

| Term | Definition |
|---|---|
| Action | A game command such as Up, Select, Back, Pause, Launch or Mute. The Input Manager produces actions from key events using TBL-KeyBinding; games react to actions, not to raw keys. |
| Active region | The part of each line and frame in which pixels are visible: 1024 × 768 in the operating mode. |
| ADV7123 | Analog Devices triple 10-bit video DAC on the DE1-SoC that converts digital RGB to analog VGA. |
| Arcade API | The C++ interface games use to draw, present frames, read input and play sounds (`setTile`, `fillRect`, `drawText`, `clear`, `present`, `pollInput`, `playSound`, `setMute`). It hides whether the FPGA or SDL2 backend is in use. |
| ASCII | American Standard Code for Information Interchange. |
| Atomic replace | Replacing a file so that readers see either the whole old file or the whole new one, never a partial file. |
| Auto-repeat | Repeated key-press events that the OS generates while a key is held. |
| AXI | Advanced eXtensible Interface; the on-chip bus protocol the lightweight HPS-to-FPGA bridge is built on. |
| Back porch | Blank interval between the end of a sync pulse and the start of active video. |
| Backend | One implementation of the Arcade API. The FPGA backend drives the DE1-SoC hardware through the HAL; the SDL2 backend draws in a window on a PC. Chosen at start-up (SR-FW-05). |
| Bank swap | The act of exchanging which tilemap bank is "front" (displayed) and "back" (writable), performed by hardware only at the start of vertical blanking. |
| BCLK | Bit clock of the codec's digital audio interface; one pulse per data bit. |
| Blanking | Intervals (front porch, sync, back porch) in which no picture is sent. |
| Bring-up mode | 640×480 @ 60 Hz video mode used during development to test the video path. |
| Codec | Coder/decoder chip that converts between digital audio samples and analog sound (here the WM8731). |
| CSV | Comma-separated values; the text format of the high-score file (decision D2). |
| D-SUB | 15-pin connector used for analog VGA. |
| DAC | Digital-to-analog converter. |
| Data flow diagram (DFD) | Diagram showing how data moves between the system's processes, stores and external entities (2.2). |
| DDR3 | Double Data Rate 3 SDRAM; the HPS main memory. |
| Display enable | Control-register bit set by the HAL once tiles and palette are loaded; until then the VGA output stays black (SR-VGA-09, SR-HAL-13). |
| DMA | Direct Memory Access; not used in this system. |
| ER diagram | Entity-relationship diagram showing tables and their keys (Chapter 5). |
| EV_KEY | Linux input-event type for key and button changes. |
| evdev | Linux generic input-event interface; exposes each input device as `/dev/input/eventN`. |
| EVIOCGRAB | ioctl that gives one process exclusive access to an input device. |
| Flash (WCAG) | A pair of opposite changes in relative luminance of 10% or more, where the darker image is below 0.80 relative luminance. |
| FPGA manager | The Linux kernel subsystem that loads the FPGA bitstream and reports fabric configuration state (e.g. via `/sys/class/fpga_manager/fpga0/state`), checked by SR-HAL-09 before any bridge access. |
| Front porch | Blank interval between the end of active video and the start of a sync pulse. |
| fsync | Linux call that writes a file's data to the storage device before returning. |
| Game Engine | The framework part of the C++ program that runs the game loop, owns the application state machine, and calls the active game through the game interface. |
| Game interface | The five operations every game implements: `init`, `update`, `render`, `isOver`, `score` (SR-FW-03). |
| Game tick | One iteration of the game loop; 60 ticks per second, locked to the display frame. |
| GPIO | General-Purpose Input/Output. |
| HAL | Hardware Access Layer; the software module that maps and accesses the lightweight bridge from Linux userspace. |
| HID | Human Interface Device; the USB device class for keyboards and mice. |
| HPS | Hard Processor System; the dual-core ARM Cortex-A9 part of the Cyclone V SoC. |
| HSYNC / VSYNC | Horizontal and vertical synchronisation pulses that tell the monitor where a line or frame starts. |
| HUD | Heads-up display; the score bar on rows 0–1 during play, showing the game name, score, lives and high score. |
| I2C | Two-wire serial bus used to write the codec's control registers. |
| inotify | Linux mechanism that reports file-system changes, used to detect a keyboard being plugged in. |
| Input Manager | The C++ module that reads the USB keyboard through evdev and turns key events into actions (SR-INP). |
| I²S | Serial format for digital audio samples, with a bit clock and a left/right clock. |
| Key code | Linux number identifying a key (`KEY_*`, for example KEY_A). |
| Latency budget | Worst-case time of each stage of a path, added up to check a timing requirement. |
| Line-out | 3.5 mm analog audio output at line level, for powered speakers or headphones. |
| LRCK (DACLRCK) | Left/right clock of the codec; one period per stereo sample frame (48 kHz here). |
| LW bridge | Lightweight HPS-to-FPGA AXI bridge; the memory-mapped interface used for all HPS↔FPGA communication in this system. |
| M10K | The Cyclone V FPGA's on-chip block RAM primitive, used to implement tilemap, tile pattern, palette and audio-related memory. |
| Main menu | The screen listing the registered games and SCORES, from which a game is started. |
| MCLK (AUD_XCK) | Codec master clock; 12.288 MHz for a 48 kHz sample rate. |
| MLAB | Memory logic array block; small distributed RAM in the Cyclone V FPGA. |
| mmap() | POSIX system call used to map a physical memory region (here, the LW bridge window) into a process's virtual address space. |
| MSEL | FPGA configuration-mode pins, set by switch SW10 on the DE1-SoC. |
| Mute | Setting that silences all sound; toggled with M. |
| Photosensitive epilepsy | Seizures triggered by flashing light or patterns. |
| PHY | Physical-layer transceiver chip (e.g. the USB PHY). |
| Pixel clock | Clock at which pixels are sent to the display: 65 MHz in the operating mode. |
| PK / FK | Primary key / foreign key of a table. |
| PLL | Phase-locked loop; FPGA block that generates the pixel clock from the 50 MHz board clock. |
| Product line | A family of products (here, games) built from one shared framework, API and hardware design. A new game reuses all of them unchanged (UR-16, QA-02). |
| Quadrant mosaic tile | One of 16 tiles that each draw a 2 × 2 block of font pixels. Combined, they display 4×-scale text with only 16 tiles of the 256-tile budget (SR-FW-12). |
| RS-343A | Analog video level standard (0 V black to 0.7 V white) used by VGA. |
| RTL | Register-Transfer Level; the hardware design abstraction written in SystemVerilog. |
| Sample rate | Number of audio samples per second per channel: 48 kHz here. |
| Scan-out | Sending one frame to the monitor, line by line from top to bottom. |
| SDL2 | Simple DirectMedia Layer 2; a cross-platform C library for windows, graphics, keyboard and audio, used by the PC simulation backend. |
| Shadow tilemap | The software-side copy of the tilemap kept in HPS process RAM; all drawing calls write here, not to the bridge, until present() copies changes to the back bank. |
| Shutdown confirmation | The box opened by holding Esc for 3 s on the main menu; Enter confirms a safe shutdown, Esc cancels (UR-19, SR-UI-14). |
| SoC | System on Chip; here the Cyclone V with HPS and FPGA on one die. |
| Square wave | Waveform that switches between two levels; gives a simple beep. |
| SRS | Software Requirements Specification; this document. |
| Stakeholder viewpoint | A group of stakeholders who share an interest in the system: interactor (player), indirect (instructor, lab staff, game developer) or domain (standards, platform). |
| Swap request | Register write by which the HAL asks the FPGA to exchange front and back tilemap banks at the next vertical blanking interval. |
| System requirement (SR) | A precise, testable statement of what the system shall do, derived from one UR (3.2). |
| TBL-GameRegistry | Compiled-in table listing every game (ID, name, menu order, factory); the menu is built from it (SR-FW-04). |
| TBL-HighScore | The top-10 scores per game, stored in the high-score CSV file on the microSD card (SR-FW-08 to SR-FW-10). |
| TBL-KeyBinding | Table mapping each (context, key code) pair to an action; `Global` entries apply on every screen unless overridden (SR-INP-09). |
| TBL-SoundEffect | Compiled-in table giving each sound effect's notes (frequency and duration); used by `playSound(effectId)` (SR-HAL-11). |
| Tile | 8 × 8 pixel graphic; the screen is a 128 × 96 grid of tiles. |
| Tile pattern RAM | Writable on-chip memory holding up to 256 8×8 px, 4bpp tile graphics, loaded at start-up. |
| Tile Renderer | The FPGA-side module that reads tilemap, tile pattern and palette memory and produces the VGA pixel stream. |
| Tilemap bank | One of two 12,288-byte buffers holding the current 128×96 grid of tile indices; one is displayed while the other is written to. |
| Tone Generator | FPGA block that makes square-wave tones and sends them to the codec. |
| Traceability matrix | Table linking each user requirement (UR) to the system requirements (SR) derived from it. |
| TRM | Technical Reference Manual (Intel Cyclone V HPS). |
| uinput | Linux interface that lets a program create a virtual input device and inject key events, used for testing. |
| UIO | Userspace I/O; a Linux driver framework, a possible future replacement for `/dev/mem`. |
| ULPI | UTMI+ Low Pin Interface; links the HPS USB controller to the USB PHY. |
| UML | Unified Modeling Language. |
| USB | Universal Serial Bus. |
| Use case | A goal-directed interaction between an actor (e.g. the player) and the system (3.3). |
| User requirement (UR) | A natural-language statement of what a stakeholder needs from the system (2.2). |
| VESA DMT | VESA Display Monitor Timing standard, which defines XGA and other modes. |
| VGA | Video Graphics Array; analog RGB video interface with separate sync signals. |
| VGA Controller | The FPGA module that generates 1024×768 @ 60 Hz VGA timing (HSYNC, VSYNC, blanking) and the pixel coordinates for the Tile Renderer. |
| vsync | Vertical sync; the signal/moment marking the end of one scanned-out frame and the start of vertical blanking, the only safe point to swap tilemap banks. |
| WCAG | Web Content Accessibility Guidelines (W3C); 2.3.1 limits flashing content. |
| WM8731 | Wolfson 24-bit audio codec on the DE1-SoC board. |
| XGA | 1024 × 768 display mode; used here at 60 Hz with a 65 MHz pixel clock. |
